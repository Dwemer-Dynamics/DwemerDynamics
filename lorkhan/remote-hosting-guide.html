Remote Hosting

Separate the game-to-server connection from the server-to-provider connections.

Which machine connects where?

  • Game → LorkhanServer: The Windows client must reach the server and use its pairing configuration.
  • LorkhanServer → AI services: The server must reach the selected language model, voice and transcription endpoints.
  • Browser → Dashboard: A working webpage does not by itself prove the game or provider connection works.

Establish a local baseline

Complete the local installation first and verify typed dialogue, voice output and microphone input separately. Keep a backup of the working configuration before moving services.

The local profile setup script reads a local DwemerDistro pairing key. Do not assume running it unchanged on a different game PC pairs that PC with your remote server.

Addresses and access

The packaged local setup uses proxy port 7514 by default. For browser access from another trusted device, use the reachable hostname or private-network address of the server host and its configured port, not a stale internal Linux address. This does not change the game bridge's loopback restriction.

Configure provider endpoints from the server’s point of view. A loopback address refers to that service’s own environment, not automatically the gaming PC.

Host an AI Service on Another Computer

  1. Get ordinary dialogue working locally first.
  2. Start the LLM, TTS or STT service on the second computer and test it there.
  3. Enable listening on a trusted network interface. Restrict access through authentication and firewall rules.
  4. Confirm LorkhanServer can reach that service address and port.
  5. Enter the address in the relevant connector, including the full chat-completions path for an LLM.
  6. Test one short interaction before moving another service.

For example, LM Studio at 192.168.1.50 on port 1234 would use http://192.168.1.50:1234/v1/chat/completions. Replace these example values with your actual service.

This is an AI provider endpoint, not the game bridge address. The current bridge is restricted to loopback endpoints; these steps do not describe direct OpenMW-to-remote-LorkhanServer support.

Keep it private

Use a trusted private network or VPN and restricted firewall rules. Treat the pairing key like a password. Do not publish configuration files, open unauthenticated providers to the internet or disable security checks to get a connection working.

This guide explains the connection boundaries; it is not a verified automated remote-client installer. Check current beta support in Discord before moving an otherwise working installation.

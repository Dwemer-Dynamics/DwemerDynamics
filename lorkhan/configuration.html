Configuration

Use LorkhanServer’s Configuration menu for shared settings, profiles, characters and services.

Quickstart

What this does: Connects LORKHAN to the services that generate dialogue, voices and microphone transcripts.

  1. Open Quickstart from the server’s top menu.
  2. Choose a language model service and supply any required API key.
  3. Choose speech output and microphone transcription services.
  4. Save the setup and test a short conversation.

The initial local speech choices are PocketTTS and Parakeet. Choosing them does not start a missing service. Check those services in DwemerDistro before testing.

Global Settings

Open Configuration → Global Settings for shared context and behaviour settings. Review the context sections, event filters, blacklists and Oghma settings there.

Checked event types are excluded from the AI context; checking more types does not add more context. Use the custom event entry only when you know the event name you want to exclude.

Profiles

Profiles collect shared model, voice and roleplay choices. Edit the default profile first, then use more profiles only when groups of characters need different behaviour.

  • Model slots: Standard, Fast, Powerful and Experimental are assigned here and selected in game.
  • Memories and diaries: Configure the profile options before expecting automatic updates.
  • Global Settings Overrides: Override supported global choices for this profile when needed.
  • Save All: Save changes before testing them.

See Language Models and Roleplay Settings for details.

LORKHAN NPCs

Select an actor to inspect its identity, biography, profile and voice. Use Voice ID for the voice assignment and Prompt Head Override for character-specific guidance.

The base ID identifies the game record; the reference ID identifies the individual actor. Names alone are not enough to distinguish repeated guards. Only put references into a shared reference group when you want them treated as the same character.

Action Editor

Review the available actions and their permissions before using Director or Cheat mode. An action can require confirmation, run without confirmation, or be unavailable according to its configuration.

Keep confirmation enabled for actions you want to approve individually. An AI request cannot make an unsupported game action work.

Playthrough Saves

Use the Dwemer Dashboard playthrough manager to inspect and manage server-side playthrough backups. These are separate from your OpenMW save files. Back up both before a beta upgrade or a deliberate restore.

Playthrough handling uses game information sent by the client. If the server appears to be showing the wrong character or history after loading a save, check the active playthrough before continuing the conversation.

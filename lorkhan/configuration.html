Configuration

Use LorkhanServer’s Configuration menu for shared settings, profiles, characters and services.

Quickstart

What this does: Connects LORKHAN to the services that generate dialogue, voices and microphone transcripts.

  1. Open Quickstart from the server’s top menu.
  2. Choose a language model service and supply any required API key.
  3. Choose speech output and microphone transcription services.
  4. Save the setup and test a short conversation.

The initial local speech choices are PocketTTS and Parakeet. Choosing them does not start a missing service. Check those services in DwemerDistro before testing.

General Settings

What this does: Sets shared behaviour and the information LORKHAN includes in conversations. Open Configuration → Global Settings; use Save All after editing.

  • Prompt & Rechat: Controls how continuing dialogue chooses its next speaker. Tight uses the listener, Conversational favours the current partner, Group rotates nearby NPCs and Random selects a mode for the chain. Strict Rechat Targeting asks the next speaker to address the previous speaker directly.
  • Memory: Controls shared memory behaviour and embedding use. Changing a retrieval setting does not generate a new diary or dynamic profile.
  • Global Connectors: Assigns models for summaries, background and memory tasks, scene classification, profile tasks, Director and relationship evaluation. These are distinct from a profile’s four conversation slots.
  • Oghma: Controls lore inclusion, topic/result limits and forced race/location context. The extractor fallback has its own connector and timeout.
  • Context: Controls observations such as magic events, transformations, item pickup value and prompt timestamps.
  • Context Selections: Chooses optional information included in the prompt. Core identity, response rules and the current turn remain necessary.
  • Misc: Includes behaviour such as the cooldown after a successful End Conversation action.

Filter noisy events without deleting your history

Checked entries in Event Type Filter are excluded from AI context. Uncheck an entry to include it. Add a custom event type by its actual recorded name, then save. This filters prompt context; it is not an instruction to delete the stored event log.

Magic, location and item blacklists use one entry per line and case-insensitive exact matches, not regular expressions. For example, an exact cell name excludes that location; a partial fragment is not a wildcard.

Profiles

What this does: Groups shared model, voice and roleplay choices so you do not have to configure every NPC individually.

  1. Open Configuration → Profiles and select the default profile, or create a new one.
  2. Give it a meaningful name. An optional slot from 1–4 makes it available through the profile-slot system.
  3. Assign the conversation models and TTS connector. Start with working services before changing roleplay options.
  4. Choose memory, diary and dynamic-profile behaviour, then click Save All.
  5. Open an NPC and confirm that it uses the intended profile before testing.
  • Default NPC: Chooses the profile used for newly discovered NPCs. Check existing NPC assignments separately.
  • Profile Prompt: Shared roleplay guidance, such as preferred reply length or conversational tone.
  • Dynamic Profile: Sets automatic update behaviour for newly discovered NPCs. The displayed option explicitly leaves existing NPC choices unchanged.
  • Middle Term Memory / Short Term Memory: Includes the corresponding memory tiers in dialogue context.
  • Diary: Auto Diary, Auto Diary Wait, Physical Diary and Include Latest Diary Entry control different parts of diary generation and use.
  • LLM Randomizer: Rotates between the profile’s response models. Leave off when comparing one model’s performance.
  • LLM Fallback: Enables retry through the assigned Fallback LLM. Assign a working fallback before relying on it.

Connector selection

Standard is normal dialogue; Fast, Powerful and Experimental are alternate slots selected in game. Diary LLM and Fallback LLM have separate jobs. TTS Connector selects the NPC speech service. Editing a shared connector affects other profiles using it.

Response, Rechat and context

Review response length/language, Rechat depth and chance, and whether Rechat may generate actions. Bored Event Chance controls eligible idle conversations. Context History Event Count limits regular history; diary and dynamic-profile event counts control their own inputs. These are limits, not guarantees that every event will be included.

Use Global Settings Overrides only when this profile should differ from the server defaults. Use Copy to all carefully: it changes the corresponding setting across profiles, not only the selected NPC.

See Roleplay Settings for practical memory and diary workflows.

API Keys

  1. Open Configuration → API Keys.
  2. Save the key under the appropriate provider, or use a supported custom key entry.
  3. Return to the LLM, TTS or STT editor and select the matching key reference.
  4. Test that connector before assigning it to a profile.

A saved key is not proof that billing, model access or region permissions are valid. A 401/403 error usually calls for checking the selected credential and account, not rewriting the NPC prompt.

Never put keys into Profile Prompt, NPC biographies or published screenshots. Local services may use No API key only when that service genuinely does not require authentication.

LORKHAN NPCs

Select an actor to inspect its identity, biography, profile and voice. Use Voice ID for the voice assignment and Prompt Head Override for character-specific guidance.

The base ID identifies the game record; the reference ID identifies the individual actor. Names alone are not enough to distinguish repeated guards. Only put references into a shared reference group when you want them treated as the same character.

Narration

Open Configuration → Narration to edit the narrator’s voice and guidance. The narrator is not an ordinary nearby actor; choosing a voice for your default NPC profile does not automatically configure it.

  1. Choose a working voice service and Voice ID.
  2. Write the narrator’s guidance in its prompt fields.
  3. Review enabled narration events, chances and cooldowns.
  4. Save, then use Narrator mode for a short deliberate test before enabling frequent automatic events.

If book reading is enabled in the Scripts menu, it uses the narrator voice. Check that voice before troubleshooting a silent book.

Player Roleplay

Open Configuration → Player for player-specific roleplay and speech. Your character name is supplied by the game. Keep biographical guidance separate from the live identity.

Player TTS speaks your submitted dialogue. It is independent of microphone transcription: turning player TTS off does not prevent voice chat. In vanilla dialogue menus, enabled player speech plays the selected option before the NPC response.

Test a short typed line after changing the player voice. If microphone input also repeats the line, investigate the speech/subtitle path rather than disabling STT.

Action Editor

What this does: Controls the supported actions AI characters may request and which require your confirmation.

  1. Open Configuration → Action Editor and select an existing action.
  2. Read its description and required parameters.
  3. Choose whether it is available and whether a Yes/No confirmation is required.
  4. Save, then test that action with a suitable nearby target.

In game, Enable AI actions must also permit execution. Director and Cheat modes do not bypass unsupported actions. Accepting a confirmation means you approved the request; check the actual game result before treating it as completed.

Do not invent a function name in the editor and expect OpenMW to implement it. See custom actions for the client/server boundary.

Prompts Manager

Use Configuration → Prompts Manager for reusable prompt documents. Use a profile’s Profile Prompt for shared character guidance and an NPC’s Prompt Head Override only for an individual exception.

Keep a copy of a working prompt before experimenting. Change one instruction at a time, save, then inspect a fresh response. LORKHAN’s normal prompting is Markdown-based; importing CHIM XML response instructions can conflict with the expected output.

Prompts influence the model. They cannot grant new game capabilities or fix a disconnected speech service.

Playthrough Saves

What this does: Keeps server-side AI history associated with the intended playthrough. It is separate from the OpenMW save file.

  1. Open DwemerDistro Home from the server menu, then the dashboard’s playthrough manager for LORKHAN.
  2. Check the selected playthrough and available saved snapshots before switching or restoring.
  3. Back up the corresponding game profile as well as the server data before a manual restore or beta upgrade.
  4. After loading a game save, check that the server shows the expected character and recent history.

When testing an older save, do not assume later AI history belongs in that earlier point in the game. Inspect the playthrough state and backup options before continuing or clearing anything. Server backups do not contain a replacement for your Morrowind save.

Local LLM Guide

Run a compatible language model service on your PC or another machine, then connect LorkhanServer to it.

Before you start

Choose a model that fits your available memory and hardware. Running the game, language model and speech services together can increase latency. A small working setup is a better starting point than several large services competing for resources.

Use an endpoint supported by the connector you choose. An OpenAI-compatible connector needs an OpenAI-compatible chat API, not the service’s browser page.

Run a Local Model

LM Studio

  1. Download and load a chat model that fits your hardware.
  2. Start its local API server and note the address, port and model identifier.
  3. Create a LORKHAN connector using Direct OpenAI-compatible endpoint. A common endpoint is http://127.0.0.1:1234/v1/chat/completions; use your installation's actual address.
  4. Save, assign it to Standard LLM in your profile, and test a short typed conversation.

See LM Studio's API guide for server controls and endpoints.

KoboldCPP

  1. Load a compatible GGUF chat model in KoboldCPP.
  2. Start its server and confirm text generation works in its own interface.
  3. Use its OpenAI-compatible chat endpoint in LORKHAN. For port 5001, this is http://127.0.0.1:5001/v1/chat/completions.
  4. Use the model identifier exposed by that server, then save and assign the connector.

The KoboldCPP wiki covers model loading and hardware settings. These ports are examples, not instructions to change a working installation.

Use the address the server can reach

LorkhanServer normally runs inside DwemerDistro’s Linux environment. 127.0.0.1 is relative to the process making the request; it is not automatically another computer or a service bound only to Windows loopback.

For a service on another machine, use its reachable address and allow only the necessary private-network access. See Remote Hosting.

Improve response time

Start with a short reply and modest context. Check model loading, memory use and request timing. Change one setting at a time, and avoid judging the model from its first cold request alone.

Do not expose an unauthenticated model endpoint to the public internet.

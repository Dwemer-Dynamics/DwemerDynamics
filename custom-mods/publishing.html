Publishing

A copy of the templates is a different mod. Give it its own repositories, name, database and branding, follow the GPL, and keep private data out of everything you share.

Your Own Repositories

  1. Open ExampleServer on GitHub and choose Use this template > Create a new repository. Then do the same, separately, for ExampleMod. You end up with two repositories you own.
  2. In each new repository, create the branches you will offer yourself, for example main and dev. A new repository from a template starts with only the default branch.
  3. Install your server copy as in Installation, using your own folder and database name, and run the smoke checks against your route.
  4. To keep taking template changes, add the template as an extra Git remote and merge by hand on your own branch. Nothing updates automatically.

Licence

Both templates are licensed GPL-3.0-only. A project based on them must follow its terms, including offering source with any binaries you share.

  • Keep LICENSE and every existing notice listed in each repository's THIRD_PARTY_NOTICES.md, including LICENSES/Original-MIT.txt, ui/HERIKA-LICENSE and third_party/nlohmann/LICENSE.MIT.
  • Add your own copyright notice to the README and THIRD_PARTY_NOTICES.md.

Launcher Manifest

Pending integration. Launcher installs from this manifest are in draft pull requests (Launcher #53, Launcher #54, Dashboard #28) with unpublished Core changes. Prepare your manifest now, but tell users to install manually until a launcher release supports it.

dwemer-mod.json sits in the repository root. Change the identity fields for your mod:

{
  "schema_version": 1,
  "id": "my-npc-mod",
  "name": "My NPC Mod",
  "description": "Short description of your mod.",
  "project_url": "https://github.com/your-account/MyNpcModServer",
  "dashboard_path": "ui/",
  "health_path": "health.php",
  "requirements": { "php": "8.2", "postgresql": true },
  "setup": {
    "config_template": "config/config.example.php",
    "config_path": "config/config.php",
    "token_placeholder": "CHANGE_ME_TOKEN",
    "database_placeholder": "my_npc_mod",
    "migrate_script": "scripts/migrate.php"
  },
  "branches": { "default": "main", "allowed": ["main", "dev"] },
  "assets": { "icon": "ui/images/icon.png", "banner": "ui/images/banner.png" }
}
  • id: 3-32 characters of a-z, 0-9 and single hyphens, starting with a letter. It cannot change after install; the folder and database (custom_<id>) derive from it.
  • project_url: your own public HTTPS repository. The launcher accepts only public HTTPS URLs.
  • database_placeholder: change it together with the database name in config/config.example.php.
  • branches: only the manifest on the default branch decides which branches are offered, and every listed branch must exist. Without it, only the default branch is offered.

Every copy must also keep config/config.php untracked (a repository that tracks it is rejected), keep 'CHANGE_ME_TOKEN' and the database name each exactly once as quoted strings in the template, keep scripts/migrate.php safe to repeat, and add no symbolic links or submodules.

Icon And Banner

  • Commit the image files and the assets entry together. Paths are relative to the repository root and must point to tracked .png, .jpg or .jpeg files; links, .., hidden folders and web addresses are rejected.
  • Use a square icon (shown at 26 x 26) and a wide banner of about 2:1. Keep each file under 4 MB.
  • Pictures come from the installed version, so users see new ones only after an update.
  • Both are optional. Replace the template's question-mark icon with your own.

Private Data Rules

Never commit, package or publish:

  • config/config.php, config/config.php.lock and config/.config-*.php (token, database password, API keys).
  • The client config.json and the paired example-client.json.
  • Backup folders, *.dump files and logs.

Publish the server as its Git repository, or a git archive of a commit, which contains committed files only. Ship the client executable with config.default.json, never with a config.json that holds a token. Keep public docs generic: no personal names, local paths, private endpoints or credential values.

CHIM Roleplay Settings

These systems shape what CHIM does between ordinary dialogue turns. They are the pages that control diaries, long-term memories, quest generation, background NPC life, screenshots, and relationship state.

Use this after your install and basic configuration are already stable.

Roleplay Settings

CHIM NPCs Menu

The CHIM NPCs menu in HerikaServer is the main profile-management page for AI characters. This is where you curate the persistent NPC records that CHIM uses for voice, personality, memory behavior, background life, and relationship state.

  • Core profile management: You can create NPCs manually, import them from JSON, assign them to profiles, and manage their saved sheet instead of relying only on whatever was generated in a live session.
  • Search and filtering: The page supports text search, profile filtering, favorites, locked profiles, dynamic profile filtering, middle-term memory filtering, auto greeting, background-life command flags, and GPS tracking flags.
  • Per-NPC control: Each NPC card surfaces race, gender, voice, RefID, Oghma tags, profile assignment, portrait selection, favorite state, and profile locking so you can quickly review whether a character is configured correctly.
  • Roleplay feature toggles: The menu is tied into systems like dynamic profiles, middle-term memory, individual memory banks, auto diaries, background life commands, and greeting behavior.
  • Bulk maintenance tools: The toolbar also exposes mass profile switching, relationship rebuilding, JSON import, and cleanup actions for unlocked profiles.

In practice, this is the page you use when a specific NPC needs hand-tuning or when you want tighter control over how CHIM treats characters across a whole playthrough.

AI Quest Manager

AI Quest Manager is CHIM's quest staging and runtime panel. It is still marked as alpha in the current UI, but it already provides the main workflow for generating and playing AI-driven questlines.

  • Scenario generation: You give it a suggestion or prompt, then it generates a quest title and briefing that can be staged.
  • Quest control: From the same page you can stage a storyline, start the quest, request a stop, and clear running quest state.
  • Live tracking: The panel shows running quests, staged quest state, the next objective, and the NPCs currently involved.
  • Reference tabs: The hub also exposes item types, NPC templates, NPC-owned templates, outfits, and quest-system server logs.
  • Practical requirement: The page warns you to send locations from the CHIM MCM first so the system can target valid places in Skyrim.

This page matters when you want CHIM to drive structured adventure content instead of only freeform NPC interaction.

Background Life

Background Life is the world-simulation map page. It tracks NPC positions, lets you inspect what off-screen characters are doing, and gives you tools to push activity back into the simulation.

  • World map view: NPCs are placed on a Skyrim map using tracked in-game coordinates so you can see where background actors currently are.
  • Per-NPC actions: The page can request a new action, request reporting, or force a coordinate refresh for an NPC.
  • Rumor system: You can create, edit, and delete rumors with hold, type, content, and lifespan fields so the background world has story prompts to react to.
  • NPC state management: The map page reads and updates metadata and extended NPC data that power background-life reporting and tracked behavior.
  • Immersion tie-in: It also surfaces letters and thought-style diary content connected to those NPCs, so it functions as both a simulation tool and a monitoring page.

In practice, this is one of the main pages for making the world feel alive when the player is not directly talking to someone.

Oghma Infinium

Oghma Infinium is CHIM's lore injection system. It gives NPCs specific world knowledge based on what they should actually know, so roleplay feels more grounded instead of every character sounding equally informed about every topic.

  • What it changes in play: A blacksmith can speak more naturally about weapons, an alchemist can know ingredient effects, and someone from a specific region can know nearby places while a stranger from another hold may not.
  • How it triggers: Oghma can be used both when you speak to an NPC and when NPCs rechat among themselves, so it is meant to shape regular play instead of only direct lore questions.
  • Setup requirement: The old guide treated Minime-T5 as the practical requirement. In the configuration wizard you enable [MINIME_T5] and [OGHMA_INFINIUM], then save and copy those settings to all profiles.
  • Main idea: Oghma helps the AI know what it should know, and just as importantly, what it should not know.

In practice, Oghma is one of the biggest reasons CHIM NPCs feel lore-aware without becoming omniscient.

Knowledge Classes And Access

Every NPC is assigned knowledge classes based on things like race, profession, location, factions, and sometimes their specific name. Oghma compares those classes against article tags before deciding what information the NPC is allowed to receive.

  • Advanced article: This is the expert version of a topic. It is for people who should know the deeper lore or specialist detail.
  • Basic article: This is the simpler layperson version of a topic. It is what a normal informed NPC might know.
  • Empty basic tags: If the basic tag field is empty, that basic article is treated as open common knowledge.
  • No matching access: If the NPC matches neither the advanced nor basic side, CHIM effectively tells them they do not know anything about that subject.

This is why one NPC can sound scholarly about a topic while another can only give a vague answer, or no answer at all.

How It Feels In Play

The old Oghma guide focused on a few simple examples that explain the system well:

  • Regional knowledge: Someone from Riften might know Northwind Summit well, while people from farther away only know a little or nothing.
  • Profession knowledge: A blacksmith, fisherman, or alchemist can speak more naturally about their own subject area.
  • Character-specific limits: If an NPC does not have the right tags for a topic like the Dark Brotherhood Sanctuary, they should not suddenly sound like an expert.

The design goal is that this knowledge appears naturally during conversation. You should not have to constantly ask "what do you know about X" for Oghma to matter.

Managing Oghma Topics

HerikaServer includes an Oghma management page so you can build or expand your own game canon instead of only using the default Skyrim knowledge pack.

  • Browse existing topics: You can search the database and inspect what is already available.
  • Add or edit topics: Each topic has a keyword name, advanced text, advanced classes, basic text, basic classes, tags, and category fields.
  • Expand for your own canon: The system is not limited to vanilla Skyrim. You can add custom topics that fit your load order and roleplay setup.
  • Reference material: The old guide also linked a public knowledge-class sheet and a Project Oghma spreadsheet for people who want to contribute more coverage.

Useful references: Oghma Knowledge Classes, Project Oghma, How we made AI NPCs smarter, How we made AI NPCs dumber on purpose.

Topic Picking And Dynamic Oghma

Oghma does not just look for one hard-coded trigger. The old guide described topic selection as a scoring pass that weighs the current response, the past response, the context summary, and the current location to decide what article is most relevant.

  • Normal Oghma: Injects the best matching current lore article into the conversation.
  • Dynamic Oghma: Updates or overrides entries when a quest reaches a specific quest ID and stage ID.
  • Partial overrides: Dynamic Oghma can leave cells empty to preserve existing values, or use clearall to wipe a field before replacing it.
  • Why it matters: This lets world knowledge change with your playthrough, instead of staying frozen forever.

Dynamic Oghma is the part that makes Oghma useful for evolving quest state, faction changes, and custom world progression rather than only static encyclopedia entries.

Soulgaze Gallery

Soulgaze Gallery is the image archive for CHIM screenshots and generated scene captures. It reads directly from the server gallery folder and gives you a simple asset browser.

  • Gallery storage: Images and videos are loaded from `HerikaServer/data/pictures/gallery/` and shown newest first.
  • Basic management: You can upload JPG or PNG files directly, open them, download them, and delete them from the gallery UI.
  • In-game capture flow: The page explicitly expects players to use the Soulgaze hotkey in-game so those pictures appear here.
  • Reimagine tools: The lightbox includes optional reimagine and animation actions that call external image providers like OpenAI, OpenRouter, and Replicate.

This is less about gameplay rules and more about preserving visual playthrough moments and turning them into reusable scene references.

Diaries

The Diaries page is the main browser and editor for CHIM diary entries. It is where you inspect the personal written record CHIM creates for NPCs and related characters.

  • Browsing: Diary entries can be explored by character, date, and full history views.
  • Export: The UI supports downloading current diaries, downloading all diary entries, and opening character diaries in a book-style reading view.
  • Editing: Individual diary entries can be edited directly from the page if you want to clean up or correct generated text.
  • Cleanup: There is also a dangerous full-delete action for wiping all diary entries.

Diaries are one of the strongest immersion layers in CHIM because they preserve private emotional perspective rather than only public spoken dialogue.

Memories

Memories are managed through the memory tab inside the Events & Memories UI. This is the long-term context layer that keeps CHIM from treating every conversation as a fresh start.

  • Memory summaries: The page shows summarized memory entries with scope, participants, period coverage, and packed memory content.
  • System status: It surfaces memory configuration, including whether embeddings are enabled and whether TXT2VEC is available.
  • Maintenance tools: You can sync memory summaries manually, edit individual summaries, delete single summaries, or wipe all summarized memories.
  • Roleplay effect: These summaries are what let CHIM keep continuity across long play sessions and changing scenes.

If memory quality feels weak, repetitive, or disconnected, this is the page to inspect before changing prompt text elsewhere.

Relationship System

The Relationship System is what lets CHIM track how characters feel about people, groups, ideas, and even specific recurring subjects over time.

  • What it tracks: It is about emotional and social state, like trust, dislike, admiration, resentment, fear, loyalty, or attachment.
  • Who it can apply to: Relationships are not limited to the player. NPCs can form changing opinions about other NPCs, factions, causes, and important world ideas.
  • How it changes: Conversations, arguments, praise, betrayal, repeated behavior, and larger playthrough events can all push a relationship in a better or worse direction.
  • What that means in play: The same character may answer very differently depending on who they are talking to and how their relationship has developed so far.
  • Separate from lore knowledge: This system is not about whether someone knows a fact. It is about how they feel.

In short, this is the system that helps CHIM characters build grudges, loyalty, affection, tension, and social history instead of treating every interaction like a clean reset.

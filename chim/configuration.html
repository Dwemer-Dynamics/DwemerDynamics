CHIM Configuration

This page is the practical map of the main CHIM configuration tabs in HerikaServer. Use it after your base install is already working.

These summaries are based on the current HerikaServer UI, not just the older wiki layout.

Configuration

General Settings

This is the global rules page for CHIM. Changes here apply broadly across conversations instead of only to one NPC or one profile.

  • Prompt and Rechat: Controls prompt head text, mood formatting, and how rechat targeting behaves.
  • Memory: Handles memory embedding, text2vec usage, and summary creation timing.
  • Global Connectors: Picks shared large language model connectors for background systems like summaries, dynamic profiles, scene classification, and director logic.
  • Context and Prompt Context: Controls what categories of game information are injected into prompts and lets you trim noisy context.
  • Misc and Translation: Covers automation, lock behavior, background-life cooldowns, and DeepL translation settings.

In practice, this is where you shape overall roleplay behavior and the shared backend logic CHIM uses outside of individual NPC profile choices.

Profiles

Profiles are the main grouping system for CHIM NPCs. Instead of configuring every character from scratch, you create reusable profile bundles and assign NPCs to them.

  • Core profile settings: Label, quick slot, default NPC behavior, default narrator behavior, dynamic profile options, and profile prompt text.
  • Connector assignment: Each profile can point to its own Standard, Fast, Powerful, Experimental, Diary, Formatter, Text-to-Speech, and Image-to-Text connectors.
  • Workflow tools: Create, clone, export, import, test all profiles, and manage profile rules.
  • Gameplay use: Profile slots support in-game hot swapping through the CHIM settings wheel.

If you want different NPC groups to roleplay differently, this is usually the most important page after installation.

API Keys

API Keys is the shared credential hub for CHIM. Connectors and services point back to keys saved here instead of asking you to paste the same credential over and over.

  • Preset providers: Includes first-class entries like OpenRouter, OpenAI, Deepgram, Google, Azure, and ElevenLabs.
  • Custom keys: Lets you save additional provider labels for non-default services.
  • Usage model: Keys are stored globally, then selected by the large language model, text-to-speech, speech-to-text, or other connector pages.
  • Testing: The current page can test some providers directly so you can catch bad credentials early.

This page is simple by design. Get the keys right here first, then do the real provider setup on the connector and profile pages.

Playthrough Manager

Playthrough Manager is the CHIM database snapshot tool. It is used to create, switch, and manage full playthrough states instead of just changing one setting or one NPC profile.

  • Public schema versus snapshots: Your active CHIM database lives in the public schema, while saved playthrough snapshots are stored separately.
  • Create snapshots: You can save the current playthrough state with a name and notes so you can come back to it later.
  • Switch playthroughs: Using Copy to Public replaces the live database with that snapshot and automatically saves your current public state first.
  • Restart required: After switching, the CHIM server needs to be restarted for the new playthrough state to fully take effect.
  • Safety and cleanup: The page prevents deleting the active profile and keeps a default baseline snapshot in place.

This is mainly for advanced use cases like separate characters, testing different story branches, rolling back after bad save states, or handling major timeline breaks without rebuilding CHIM from scratch.

Narration

This section maps to the HerikaServer Narrator Management page. It controls how The Narrator behaves, sounds, and participates in the playthrough.

  • Core narrator behavior: Enables or disables narrator features like welcome lines, random comments, bored comments, and diary-related behavior.
  • Inline narration: Controls whether asterisked narration is spoken by The Narrator voice, stays on the NPC voice, or is disabled.
  • Quest comments: Lets the narrator react to quest objective updates with chance and cooldown controls.
  • Profile and voice: Assigns the narrator profile, text-to-speech voice id, and related Oghma knowledge tags.
  • Advanced control: Includes narrator action toggles, dynamic profile behavior, and narrator-specific prompt overrides.

Use this page when you want to tune narration flow specifically, rather than changing all NPC roleplay globally.

Player Roleplay

This section maps to the HerikaServer Player page. It is the player-facing roleplay sheet CHIM uses for your character identity, how NPCs understand you, and how your own speech and diary behavior are framed.

  • Player identity: You can define the player name, appearance, and bio so CHIM has a stable roleplay description of who your character is.
  • Who knows your bio: The page includes a visibility toggle for whether that bio is broadly known or treated as more limited context.
  • Speech style: You can write your own player speech style or generate one from recent dialogue so CHIM better preserves your character voice.
  • Player diary and voice: It also controls player diary participation plus player-specific text-to-speech connector and voice overrides.
  • Tracked character state: The page surfaces live equipment, inventory, skills, and categorized Skyrim stats so the player profile stays grounded in the current playthrough.

Use this page when you want CHIM to treat the player as a more defined roleplay character instead of only a generic input source.

Action Editor

Action Editor controls which gameplay actions CHIM can expose to AI and in which scopes those actions are allowed to run.

  • Enable or disable actions: Persistent overrides let you turn individual actions on or off without touching the shipped base catalog.
  • Scope management: Actions can be filtered by NPC, follower, narrator, and dynamic scopes.
  • Dispatch and metadata: The page surfaces how actions are routed, including server-side versus game-side execution details.
  • Catalog visibility: You can inspect active actions, descriptions, and state before changing them.

This is not usually a first-run page. It matters when you want to limit, expand, or debug what CHIM is allowed to actually do beyond speaking.

Prompts Manager

Prompts Manager is the advanced prompt override system for CHIM. It lets you inspect default prompts, add custom replacements, and revert when needed.

  • Default versus custom: You can compare the shipped baseline prompt against your own override.
  • Prompt browsing: The table is searchable by key, description, status, and preview text.
  • Edit and clear workflow: You can override only the prompts you care about, then clear them later to fall back to default behavior.
  • Import and export: Custom prompt overrides can be moved around by CSV.

This page is for advanced tuning. Small prompt changes can have large roleplay effects, so it is best used after the rest of the setup is already stable.

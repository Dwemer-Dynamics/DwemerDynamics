STOBE Configuration

This page explains the main STOBE setup pages inside StobeServer in plain language. Use it after installation when you want to tune how STOBE behaves across your playthrough.

Global Settings

What this page does: This is the main global behavior page for StobeServer. Changes here affect the overall AI behavior for the whole save, not just one NPC.

  • Prompting: This is where StobeServer stores the main prompt head, emote mood list, general instructions, and roleplay instructions.
  • Rechat: Controls how STOBE chooses follow-up speakers, including rechat mode, strict targeting, and whether the original player speaker can be selected again.
  • Memory: Covers the global memory system, dynamic profile timing, and how much older context STOBE keeps bringing back into play.
  • Compact Chat History: Keeps older conversation context shorter so more room remains for the current scene.
  • World Knowledge: Can automatically include matching race, location, and character knowledge when those names appear in the current context.
  • Relationship System: This is where the shared relationship layer is turned on or off for server-side interaction tracking.
  • Player Faction: Lets you define a custom player-faction name and an optional extra prompt block for how that faction should be treated.
  • Context Selections: Lets you choose which context blocks and subsections STOBE includes in system prompts.

Profiles

What this page does: Profiles are reusable behavior presets for NPCs and factions. Instead of hand-tuning everyone one by one, you build profile setups and assign NPCs to them.

  • Basic profile setup: Each profile has a label, can be marked as a default NPC profile, and can also be marked as a player-faction profile.
  • Main prompt text: Profiles carry both a Prompt Head and a Profile Prompt, which shape the behavior style of NPCs using that profile.
  • Response modes: Each profile has Standard, Fast, Powerful, and Experimental LLM choices. You can switch the active mode from the in-game chat box.
  • Other connectors: Profiles also choose their Diary, Autochat, Memory, Background Life, Dynamic Profile, Relationship, and TTS connectors.
  • Dynamic profile behavior: Profiles decide whether STOBE can rewrite fields like personality, speech style, and goals over time.
  • Diary behavior: Profiles also control auto-diary behavior, including how often entries can be written and how many events are needed first.
  • Workflow tools: The page supports cloning, exporting, importing, profile testing, assignment rules, and copying individual settings to other profiles.

Stobe NPCs

What this page does: This is the main character manager. Open an NPC to edit its profile, voice, memories, relationships, and roleplay fields.

  • Protect profiles: Lock a profile to protect it from rollback. Use View History to review and restore an older version.
  • Bulk controls: Unlock all NPC profiles when you need to make broad changes, then use Auto Lock Profiles on Edit if edited profiles should lock again after saving.
  • Filters: Search and filter by favorites, locks, dynamic profiles, memory, tags, and player-faction membership.

API Keys

What this page does: This is the shared API key page for StobeServer. You save provider keys here once, then the connector pages reuse them.

  • Preset providers: The current built-in presets include OpenRouter, OpenAI, Groq, Nano-GPT, Google, Cartesia, and Inworld.
  • Used across the server: These saved keys are then selected by the Large Language Model and Text-to-Speech connector pages.
  • Custom key rows: You can also add your own named API badge entries for other supported services.
  • Practical use: If a connector needs a cloud login, this page is usually where that key gets stored first.

OpenRouter is optional. Follow Use Your Own LLM Provider to connect STOBE to another compatible hosted or local service.

Narrator

What this page does: This page controls the STOBE narrator layer, including when it speaks, what profile it uses, and how it presents itself.

  • Name and identity: Give the narrator its own display name, profile, voice, and character description.
  • Core toggles: You can turn the narrator on or off, enable welcome narration, random narration, and narrator diaries.
  • Chance and cooldowns: The page controls welcome cooldown, random narration chance, and random narration cooldown.
  • Profile and voice: You choose which profile the narrator uses, its voice ID, and which world-knowledge tags it should pull from.
  • Prompt override: There is also a narrator-specific prompt-head override if you want the narrator to follow special instructions.
  • Dynamic profile updates: The narrator can also use dynamic updates for personality, speech style, and goals if you turn that on.
  • Inline narration: Choose whether scene descriptions use the narrator voice, the NPC voice, text only, or stay disabled.

TTS Studio / Voices

What this page does: Test voices, rebuild supported voice libraries, and manage voice samples without editing files by hand.

STOBE includes race-based voices and unique voices for named NPCs. General male and female voices remain available when no specific match is found.

Rename Names

What this page does: Manage the lore-friendly name pool used for generic NPCs. Add names one at a time or import a CSV, then enable or disable entries without deleting them.

Named and unique characters are protected from this generic renaming system.

World

What this page does: The World page has separate World Knowledge and World State views.

  • World Knowledge: Add lore, aliases, tags, and custom descriptions that help characters understand names mentioned in a scene.
  • World State: Review the current vanilla and mod-added world states. Enable a prompt addendum when that state should change how matching lore is explained.

Descriptions

What this page does: STOBE automatically saves descriptions from items and equipment it detects in game. Use this page to review them or add custom descriptions for missing and modded items.

CSV import and export are available for larger collections, and custom rows override matching base entries.

Action Editor

What this page does: Action Editor controls which server-side actions STOBE is allowed to use and whether they are active.

  • Enabled state: You can turn individual actions on or off without changing the shipped base rows.
  • Search and filtering: The page supports live search plus enabled and disabled filters so you can find specific actions faster.
  • Base versus custom: STOBE keeps track of which actions are still stock and which ones now have custom override rows.
  • What you are editing: The list shows the command name, visible action name, description, and current enabled state.
  • Practical use: This is mainly the page to visit when you want to stop a specific AI action from being used or re-enable one that is off.

Prompts Manager

What this page does: Prompts Manager is the page for editing STOBE's built-in prompt text one prompt at a time.

  • Default versus custom: Each prompt key keeps its shipped default text and an optional custom override.
  • Edit and clear: You can write a replacement prompt for any key, or clear it to fall straight back to the default.
  • Description: The page also shows a short description for what each prompt is for before you change it.
  • Import and export: Custom prompt changes can be exported as CSV and imported again later for backup or sharing.

Playthrough Saves

Keep a separate AI history for each campaign. These saves hold STOBE conversations, memories and character state; keep saving your game normally too.

  • Choose a playthrough: Use the picker on the server home page to switch or start a new playthrough. Read the save details before choosing.
  • Save and transfer: Open Playthrough Management to manage your saves. Download a save for backup or import one when moving your AI history.
  • Automatic switching: Turn on Automatically switch playthroughs in the storage controls to match your loaded campaign. This is off by default. Reload your game save after enabling it and follow any prompt to associate an existing playthrough.
  • Before switching: The current AI progress is saved before the other playthrough is loaded.
  • Loading an older game save: AI history follows the game timeline. Automatic recovery saves use the Game days behind threshold. Check the recovery message and saved playthroughs if you need the later AI state.
  • Cleanup: Storage and Cleanup lets you choose which categories to clean and how old entries must be. Event cleanup is off by default. Review the category carefully before deleting anything.

Profile Updates And Event Filters

Choose how often characters develop and which events they use in conversation.

  • Profile timing: Set the dynamic-profile interval in the web settings, in game hours. Check the selected profile and any NPC override when one character needs a different schedule. The old game-menu timer is no longer the place to set it.
  • Event Type Filter: Tick an event type to exclude it from conversation context. Add a custom event type when it is not listed. This does not delete the saved event.
  • Voice: See Voice Tools for voice effects and pronunciation changes.

Player Speech

Open the Speech-to-Text settings to choose how microphone audio becomes text. The player dialogue audio setting controls whether the player's words are spoken aloud.

Follow Speech-to-Text for recording setup. Player-faction profiles remain separate from ordinary NPC profiles.

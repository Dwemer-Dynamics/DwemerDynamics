STOBE Log Files

When STOBE is failing, the fastest fix is usually finding the right log first instead of guessing. This page keeps the useful STOBE, RE_Kenshi, and DwemerDistro log locations in one place.

Log Files

STOBE Mod Log

This is the first log to open for the STOBE mod itself.

Kenshi\mods\Stobe\stobe.log

Use this when STOBE is not reacting in game, the hotkeys are failing, context capture looks wrong, or the mod is not connecting to StobeServer.

RE_Kenshi Log

This is the main loader-side log for the Kenshi runtime.

Kenshi\RE_Kenshi_log.txt

Use this when STOBE is not loading at all, RE_Kenshi.exe is failing to bring the plugin up, or the STOBE DLL never starts.

STOBE Config Files

If the mod is loading but connecting to the wrong place or acting strangely after an update, also check the live STOBE config files:

Kenshi\mods\Stobe\Stobe.ini

Kenshi\mods\Stobe\StobeCustom.ini

Stobe.ini is the shipped baseline, while StobeCustom.ini keeps the user or runtime overrides that survive updates.

STOBE Server Logs

Use either of these when the mod loads but the server, model, or voice service fails:

  1. StobeServer: Open Control Panel, then Server Logs.
  2. Distro Launcher: LOGS then Generate Distro Debugging Logs.

The launcher saves the complete diagnostic file here:

Desktop\DwemerDistro-Diagnostics\diagnostics-YYYYMMDD-HHMMSS.txt

Upload that diagnostic file together with stobe.log when asking for support. Include RE_Kenshi_log.txt when STOBE did not load at all.

Generate Logs In Game

Use Generate Logs from the in-game menu to collect a support report.

  • Include context: Give the NPC name, what you were doing, and what you expected.
  • Save or scene problems: Include the recovery message or Director status shown when the problem happened.
  • Microphone problems: Say whether recording started, your words appeared, and a reply played.
